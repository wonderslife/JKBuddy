## 1. 背景与目标

### 1.1 现状与样例界定

- **若依（RuoYi）**：各业务系统基于 Spring Boot，统一承载组织、角色、菜单与**数据权限**（`sys_user` / `sys_role` / `sys_dept` / `sys_role_dept` / `sys_role_menu`）。
- **资产系统（本样例）**：资产管理 / 资产处置业务系统，**使用自己的数据库**，并含**审批流程**与**多系统协同**能力（如产权交易平台、拍卖平台、评估机构、税务等）。
  - ⚠️ **明确不使用 `<db-name>` 库**：该库属于**投资系统**（投资问数 DWD 视图），不在本改造样例范围内。
- **MCP Server 规划（每业务系统独立）**：
  - **投资系统** → 由**独立的 MCP Server**（`mcp-inv-server-v2`）承载其业务（DWD 问数等），不在本文档范围内。
  - **资产系统（本样例）** → 由**另一套 MCP Server**（协议适配层）承载，见本文档。
- **mcp-inv-server-v2**：Python/FastMCP 服务，承载**投资系统**业务；其认证机制（[middleware.py](mcp-inv-server-v2/src/inv_mcp_v2/middleware.py)）可作为资产系统 MCP Server 的**实现参考**。
- **LibreChat 多 Agent**：A1 意图路由器 → A2 数据执行器 / A3 系统处理 / A4 文件导出 / A5 审批 / A6 跨系统协同（见 05 文档）。

### 1.2 改造动因

1. **绕过若依业务层**：若直接对业务库表做只读查询，未经过若依 `@DataScope` / `@PreAuthorize`，无法保证行级数据权限与若依一致。
2. **能力单一**：仅查询，无法承接资产处置审批、多系统协同等业务动作。
3. **身份与权限脱节**：MCP 的 `client_id/role` 与若依用户体系无关联，无法按若依数据权限返回数据。

### 1.3 改造目标

- **MCP 化改造**：将资产系统的**查询、审批、多系统协同**能力封装为 MCP 工具，供智能体调用。
- **统一数据权限**：MCP 解析当前用户身份，把**数据权限上下文传递到若依**，由若依 `DataScopeAspect` 统一行级过滤，杜绝越权。
- **安全承接审批**：资产处置等审批动作经若依 REST 接口，由 `@PreAuthorize` + `@DataScope` 二次鉴权。
- **多系统协同**：资产数据与产权交易 / 拍卖 / 评估等外部系统的协同动作，同样经若依身份与数据权限校验后执行。
- **更便于接入智能体**：以数据权限为核心的 MCP 能力层，让智能体在合规范围内安全问数、办事。

## 2. 目标架构（改造后）

```
智能体（LibreChat 多 Agent：A1→A2/A3/A4/A5/A6）
        │  MCP 协议调用
        ▼
MCP Server（资产系统 MCP Server，协议适配层）
   ├─ 身份层：解析 SSO loginName，透传已认证身份
   └─ 服务层：查询 / 审批 / 多系统协同 工具适配器
        │  REST 调用（携带已认证身份）
        ▼
若依 - 资产系统（Spring Boot，独立数据库）
   ├─ @DataScope：依据当前登录用户自行判定数据范围并过滤（查询）
   ├─ @PreAuthorize：功能/操作鉴权（审批等写操作）
   ├─ 业务 Service / 资产处置审批流程
   └─ 多系统协同（产权交易 / 拍卖 / 评估 / 税务等）
        ▼
资产系统数据库（<asset-db>，非 <db-name>）
```

**核心原则**：MCP 是**薄协议适配层**，只负责"解析并透传已认证身份 + 工具路由"；**数据权限由若依服务端依据当前登录用户自行判断**，agent / MCP 不做任何数据权限的分类识别。数据过滤与最终鉴权始终在若依（资产系统）端完成。

## 3. MCP-化改造总体方案（分层）

| 层 | 职责 | 说明 |
|----|------|------|
| **L0 协议层** | MCP（Streamable HTTP）对外暴露工具 | FastMCP，端口、鉴权沿用现网配置 |
| **L1 身份层** | 解析并透传已认证身份 | SSO `loginName` → 透传给若依 |
| **L2 透传层** | 透传身份，不计算数据权限 | 数据权限判定收敛在若依（见 §4） |
| **L3 服务层** | 查询 / 审批 / 多系统协同 工具适配器 | 调用资产系统若依 REST 接口 |
| **L4 治理层** | 日志、审计、限流、异常映射 | 每次调用留痕 |

### 3.1 工具清单规划（资产系统样例）

| 工具组 | 示例工具 | 通道 | 数据权限 |
|--------|---------|------|---------|
| 查询 | `asset_query` / `asset_detail` / `asset_stat_*` | 若依 REST | 传递权限，若依过滤 |
| 审批 | `approval_submit` / `approval_todo` / `approval_opinion` / `approval_records` | 若依 REST | @PreAuthorize + @DataScope |
| 多系统协同 | `collab_push_to_trade_platform` / `collab_query_auction` / `collab_evaluation_request` | 若依 REST | 身份 + 数据权限校验 |
| 导出 | `export_to_excel` | 若依 / 代码沙箱 | 基于已授权查询结果 |
| 系统 | `get_ontology` | 本地 | 只读 |

> 工具语义依赖资产系统本体（见 [04 文档](04-本体层落地与组件边界设计.md) 的本体边界方法论），此处为占位命名。

### 3.2 与投资系统的边界

- **投资系统**：由独立 MCP Server（`mcp-inv-server-v2`）承载，使用 `<db-name>` / DWD 视图，与本文档**相互独立**。
- **资产系统（本样例）**：由**另一套独立 MCP Server** 承载，本文档聚焦其查询 / 审批 / 多系统协同能力。
- 两套 MCP Server 各自对接各自的若依业务系统，**不共享业务库、不交叉引用**。

## 4. 数据权限设计（核心）

### 4.1 若依数据权限模型回顾

| 元素 | 表 | 作用 |
|------|-----|------|
| 用户 | `sys_user` | `user_id`, `dept_id`, `user_name`, `status`, `del_flag` |
| 角色 | `sys_role` | `role_id`, `data_scope` |
| 用户-角色 | `sys_user_role` | 用户角色关联 |
| 部门 | `sys_dept` | `dept_id`, `ancestors`（支持"本部门及以下"） |
| 角色-部门 | `sys_role_dept` | `data_scope=2`（自定义）时记录可见部门 |

**data_scope 取值**：`1`=全部、`2`=自定义、`3`=本部门、`4`=本部门及以下、`5`=仅本人。

### 4.2 身份解析：SSO loginName → sys_user

1. MCP 认证中间件校验请求，取得**蓝凌 SSO loginName**（或 JWT/OAuth2 中可识别用户的字段）。
2. 校验用户有效性：`status != '1'` 且 `del_flag != '2'`（沿用现有用户库校验约束），无效则拒绝。
3. MCP 仅把**已认证身份（loginName）**透传给若依；**禁止客户端自报 user_id / data_scope**。
4. 用户身份映射与数据权限判定，全部由**若依服务端**依据其会话中的当前登录用户完成。

### 4.3 数据权限判定（由若依服务端负责）

**核心原则**：数据权限上下文**由若依服务自行判断，agent 端（A1/A2）与 MCP 均不做任何数据权限的分类识别**。

- MCP / agent 只传递业务意图与已认证身份，**不计算、不识别、不传递数据范围**。
- 若依 `@DataScope` 依据其**当前登录用户**（`sys_user` → `sys_user_role` → `sys_role.data_scope` → `sys_role_dept` / `sys_dept.ancestors`），自行计算并追加行级过滤：

| 步骤 | 依据 | 结果 |
|------|------|------|
| 用户→角色 | `sys_user_role` | `role_ids` |
| 角色→范围 | `sys_role.data_scope` | `1`=全部、`2`=自定义、`3`=本部门、`4`=本部门及以下、`5`=仅本人 |
| 自定义范围 | `sys_role_dept` | `data_scope=2` 时的 `dept_ids` |
| 部门及以下 | `sys_dept.ancestors` | `data_scope=4` 时的 `ancestorDeptIds` |
| 管理放行 | `data_scope=1` / admin 角色 | 全量，不加过滤 |

> 上述判定完全发生在若依服务端，与 agent / MCP 无关，保证口径一致、不可被客户端篡改。

### 4.4 传递方式（仅透传身份，转发给若依）

- **查询**：MCP 调用资产系统查询 REST 接口时，仅携带**已认证身份**；若依 `@DataScope` 依据当前登录用户自行追加 `dept_id IN (...)` / `user_id = ...` 过滤。
- **审批/写操作**：仅携带身份，由若依 `@PreAuthorize` 校验功能权限、`@DataScope` 依据登录用户校验数据范围后再执行。
- **多系统协同**：仅携带身份，经若依校验授权后，才与外部系统交互。
- **不变量**：agent / MCP 不计算、不拼接行级过滤，数据权限判定完全收敛在若依。

### 4.5 各场景细则

#### 查询场景

```
MCP 收到查询 → 解析 loginName → 仅透传身份
      → 调用资产系统查询接口（携带身份）
      → 若依 @DataScope 依据登录用户判定数据范围并过滤 → 返回受控数据
```

- 管理员看全量；普通用户仅见其数据范围内的资产记录。
- 若用户无任何可见部门且非管理员 → 返回空集或"无权限数据"，**不报错泄露结构**。

#### 审批场景（资产处置审批）

```
MCP 收到审批请求 → 解析身份 → 仅透传身份
      → 调用资产系统审批接口（如 /asset/approval/submit）
      → 若依 @PreAuthorize 校验操作权限 + @DataScope 依据登录用户判定数据范围
      → 通过则执行资产处置审批流转；未通过则返回 403
```

- **MCP 不代批**：最终是否放行由若依裁决。
- 审批动作属高权限操作，数据范围由若依依据登录用户判定，未授权如实拒绝。

#### 多系统协同场景

```
MCP 收到协同请求 → 解析身份 → 仅透传身份
      → 调用资产系统协同接口（如推送产权交易平台 / 查拍卖状态 / 发起评估）
      → 若依依据登录用户校验授权与数据范围 → 与外部系统交互 → 返回结果
```

- 协同动作属跨系统高风险操作，数据权限由若依判定，须校验授权与目标系统一致性后方可执行。

#### 导出场景

- 导出基于**已授权查询结果**（已过数据权限过滤），不引入未授权数据。
- 通过若依或代码沙箱生成文件，返回下载链接。

### 4.6 数据权限安全不变量

| 不变量 | 说明 |
|--------|------|
| 判定在若依 | 数据权限上下文由若依服务端依据当前登录用户自行判断，**agent/MCP 不做分类识别** |
| 服务端解析身份 | 禁止客户端自报 user_id / data_scope |
| 若依端裁决 | 行级过滤与动作鉴权在若依，agent/MCP 不计算、不拼过滤 SQL |
| 最小可见 | 多角色取最严 data_scope |
| 管理放行 | 仅 `data_scope=1` / admin 可见全量 |
| 审计留痕 | 每次查询/审批/协同记录发起人、范围、时间 |

## 5. 与智能体接入的衔接（05 文档落地）

- **A2 数据执行器**：调用"查询"类 MCP 工具时，工具内部自动完成身份解析 + 权限上下文装配，A2 无需感知权限细节。
- **A5 审批处理**：调用"审批"类 MCP 工具，由若依鉴权，MCP 透传结果（成功/403）。
- **A6 跨系统协同**：调用"多系统协同"类 MCP 工具，经若依授权后与外部系统交互。
- **A4 文件导出**：基于已授权结果导出。

> MCP 权限层对智能体透明：智能体只需表达业务意图，数据权限由 MCP+若依在链路内强制。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| MCP 与若依权限口径不一致 | 过滤收敛在若依，MCP 不拼 SQL |
| 身份映射失败（loginName 对不上） | 校验失败即拒绝，不降级放行 |
| 权限缓存过期 | 短 TTL + 变更失效 |
| 审批越权 | 若依 `@PreAuthorize` + `@DataScope` 双校验，MCP 不代批 |
| 跨系统协同动作高风险 | A6 须校验授权与目标系统一致性 |

---

## 8. 验收标准（评审通过后）

1. 普通用户查询资产数据**仅含其数据权限范围内**的记录，与资产系统页面口径一致。
2. 管理员可见全量；无权限用户返回空集而非报错。
3. 审批动作未经授权返回 403，MCP 不代批、不放行。
4. 多系统协同动作未经授权不发起外部交互。
5. 身份解析失败时请求被拒绝（不降级）。
6. 每次查询/审批/协同均留有审计记录（发起人、范围、时间）。
